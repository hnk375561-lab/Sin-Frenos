# Fase 7 — Reauditoría funcional después del rebuild cromático

## Resultado general

La reauditoría se hizo sobre la base del cambio cromático de la Fase 6 sin cambiar layout, copy, rutas, sitemap, catálogo ni generación estática. El objetivo fue buscar regresiones donde el color comunica estado o disponibilidad, no volver a discutir la dirección visual.

## Correcciones realizadas

### Severidad alta: contraste del CTA dominante

El texto blanco sobre el magenta `#FF2E88` tenía un contraste de **3.50:1**, insuficiente para texto normal según WCAG AA. Se corrigieron los CTA y botones que usan el magenta como fondo para usar texto ultravioleta `#171130`, que alcanza **5.17:1**. El magenta no se eliminó ni se suavizó: se conservó como acción dominante y solo se cambió el color del texto.

La excepción son íconos grandes o marcas aisladas donde el texto no funciona como label de control; se revisaron separadamente.

### Severidad media: estados de publicaciones propias

`/mis-publicaciones` todavía tenía badges `amber/emerald/blue` de la identidad previa. Se remapearon para que los estados no se confundan:

| Estado | Tratamiento |
|---|---|
| Borrador | Neutral de superficie |
| En revisión | Cian claro + texto cian oscuro |
| Publicado | Lima clara + texto lima oscuro |
| Pausado | Neutral de superficie |
| Vendido | Rosa/magenta claro + texto magenta oscuro |
| Eliminado | Rojo de error semántico |

### Severidad media: restos de relaciones cromáticas anteriores

Se eliminaron gradientes teal, naranja, azul petróleo y púrpura heredados en hero, categoría, foco y sombras de la capa marketplace. Se reemplazaron por cian señal, magenta eléctrico, ultravioleta y variantes del sistema Phase 6.

## Edge cases revisados estáticamente

Se inspeccionaron inputs con `required`, `noValidate`, `aria-invalid`, `role="alert"`, estados `disabled`, límites `MAX_PHOTOS`, upload de fotos, loaders, focus rings, `prefers-reduced-motion`, `overflow-x`, posiciones `fixed` y animaciones. La lógica de máximo de fotos y revocación de object URLs de Fase 4 continúa presente. Los formularios conservan mensajes de error específicos y no dependen solamente de color.

Los estados de sesión expirada o falta de credenciales siguen mostrando gates existentes; no se agregó una falsa sesión ni se alteró el flujo Supabase.

## Límites honestos

No hay Playwright instalado ni un navegador automatizado integrado al repositorio. No fue posible verificar aquí Chrome Android, Safari iOS, Firefox desktop, Safari desktop, teclado virtual real, forced colors del sistema ni rendering real de emails.

Tampoco existen templates de email dentro del repositorio para revisar. El email del magic link es administrado por Supabase, por lo que debe verificarse en el dashboard/proyecto Supabase con un envío real.

Antes de publicar, una persona debe hacer un walkthrough en Chrome desktop a 1440 px y una ventana ultra-wide, Firefox/Safari desktop, Chrome Android y Safari iOS a 390 px y 360 px. Debe probar especialmente foco de teclado, teclado abierto en mensajes, submit deshabilitado, upload de 0/1/máximo/exceso de fotos, sesión expirada durante wizard y una vista real del email magic-link.
