# Auditoría UX/UI y dirección de producto — Sin Frenos

## Diagnóstico inicial

Sin Frenos es una aplicación **Next.js 16 con export estático**, React 19, Tailwind 3, Supabase para el marketplace y un bundle generado de fichas técnicas. El repositorio contiene 40+ rutas funcionales para catálogo, fichas, comparador, favoritos, rankings, guías, financiamiento, publicación y gestión de listings. El catálogo tiene 250 vehículos y 239 imágenes locales procesadas; el árbol `public/` concentra aproximadamente 287 MB en el checkout auditado.

La home previa funcionaba como una composición editorial de “archivo automotor”: marketplace vacío al inicio, hero de compra/venta, buscador técnico relegado, varias secciones de índice, fabricantes, rankings, dossiers, FAQ y calculadora. El problema no era falta de contenido, sino **competencia de propuestas**: un visitante recibía simultáneamente un archivo técnico, un marketplace sin publicaciones y una página editorial larga. La ausencia de publicaciones reales dejaba un bloque grande vacío en el primer pantallazo, mientras que la acción de buscar quedaba visualmente secundaria.

El header previo tenía seis enlaces de navegación en mayúsculas, un CTA de publicación, varios íconos utilitarios y un enlace persistente de “Evidencia citada”. Su lógica era correcta, pero visualmente se percibía como una herramienta técnica y no como un producto de compra/venta. En móvil, el menú escondía parte de la arquitectura de producto detrás de un patrón de navegación genérico.

## Decisiones de producto

La nueva dirección usa una metáfora de **showroom + marketplace**. El primer pantallazo responde qué es Sin Frenos, qué puede hacer el visitante y cuál es la acción siguiente. La búsqueda aparece dentro del hero, junto con acceso directo a publicaciones y fichas. Una ficha real del catálogo funciona como ancla visual del producto sin inventar publicaciones.

El catálogo técnico pasa a ser una capa de confianza y decisión: categorías, fichas destacadas, comparador, rankings y financiamiento. La publicación mantiene su posición como segunda conversión. El sistema queda preparado para incorporar publicaciones destacadas, vendedores profesionales y nuevas categorías de vehículos sin rehacer la navegación.

## Implementación

- Home reemplazada por una composición comercial con hero, búsqueda, showcase real, métricas, categorías, fichas destacadas, herramientas de decisión, financiamiento, preguntas frecuentes y CTA de publicación.
- Nuevo componente `CommercialVehicleCard` con imagen dominante, fabricante/modelo, año, potencia, tipo, precio/ficha y favoritos.
- Header global reconstruido con navegación orientada a tareas: Comprar, Explorar, Comparar, Marcas y Guías; CTA de Publicar; búsqueda global; favoritos, tema, cuenta y menú móvil.
- Marketplace `/listings` reestructurado para priorizar intención de búsqueda, filtros en una superficie unificada, skeletons y estados vacíos honestos.
- Cards de listings y estilos de formularios actualizados para mantener coherencia visual en compra y publicación.
- Metadata global y tagline actualizados para reflejar marketplace + fichas + comparación.
- No se modificaron tablas, queries, autenticación, Supabase, rutas de fichas, comparador, favoritos, favoritos de listings ni wizard funcional de publicación.

## Performance y accesibilidad

La home reutiliza las imágenes optimizadas y el loader existente, pide `priority` solamente para el hero y las primeras tarjetas, usa `sizes` explícitos y mantiene carga diferida para el resto. No se duplicaron imágenes ni se agregaron assets binarios. Los estados de listings distinguen carga, error, vacío y resultados. Los CTAs y controles conservan foco visible, labels, `aria-label`, navegación de teclado, soporte para `prefers-reduced-motion` y áreas táctiles adecuadas.

## Validación final

Antes de editar, el baseline pasó `npm run type-check`, `npm test -- --run` y `npm run lint`, con 28 archivos de test y 458 tests exitosos. Después de la implementación final volvieron a pasar `npm run type-check`, `npm run lint` y `npm test -- --run` con **458/458 tests**.

También pasaron `npm run verify:min-count`, `npm run verify:content`, `npm run verify:relations`, `npm run verify:manufacturer-slugs`, `npm run verify:reserved-keys` y `npm run verify:seo`. La última verificación SEO confirmó `robots.txt` y `sitemap.xml` con 841 URLs en el export estático. `npm run build` terminó correctamente: Next.js compiló, tipó, generó 1.334 páginas estáticas y reutilizó 2.868 variantes de imagen optimizadas.

La home rediseñada fue inspeccionada en navegador en desktop: el título, buscador, showcase, categorías, cards, herramientas, FAQ y CTA final aparecen en el orden esperado; el estado de marketplace vacío no simula ofertas. Las rutas `/listings/` y `/publicar/` también fueron abiertas; el shell, footer y estados de carga renderizan sin errores de consola. En este entorno las vistas de marketplace quedan en carga porque no están configuradas `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`, advertencia ya documentada por el proyecto y no causada por el rediseño. No se agregó un fallback de publicaciones inventadas.

El servidor de desarrollo usado para la inspección fue detenido al finalizar. No quedan archivos eliminados; el bundle generado fue actualizado por el build para excluir el fixture inválido temporal que estaba embebido en el artefacto anterior.
